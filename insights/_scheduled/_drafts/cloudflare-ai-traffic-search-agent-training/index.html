CloudflareのAIトラフィック3分類と9/15デフォルト——発見経路を誤遮断しない

CloudflareがAIトラフィックをSearch / Agent / Trainingに分け、2026年9月15日から新規ドメインの既定を変える。Training遮断のつもりがSearch発見まで落とすリスクを整理する。

WHAT CHANGED｜何が変わったか

Cloudflareは2026年7月1日のChangelogで、AIクローラーを「何をするか」で分けて制御できる選択肢を、Freeプランを含む全顧客に広げたと発表しました。分類は3つです。Search（あとで質問に答えるために索引する）、Agent（チャットの取得ボットやブラウザ利用エージェントなど、人の代理でリアルタイムに動く自動化）、Training（学習やファインチューンのためにコンテンツを取るクローラー）です。

各分類について、全ページで遮断する、広告を表示しているページだけ遮断する、遮断しない、を独立に選べます。公式の趣旨は、「読者や収益を戻す自動化は残し、コンテンツだけを取る自動化は止められるようにする」ことです。

加えて、2026年9月15日から、Cloudflareに新規接続するドメインには更新された既定が入ります。TrainingまたはAgentと分類されたボットは、広告を表示しているページで遮断され、Searchは許可されたままです。同じ日、SearchとTrainingを兼ねる多目的クローラーは、Training遮断の新しい既定の影響を受けます。新しい既定は、9月15日より前にオプトアウトできます。

WHY IT MATTERS｜発見経路を誤遮断する理由

ARIのVisibilityは、「AIやエージェントに見つけられ、読めるか」が入口です。Trainingを止めたい意図は理解できます。ただし、1つのスイッチで「AI全部」を止めると、Search分類まで落ち、比較や推薦の材料として公式ページが使われにくくなる可能性があります。

CloudflareのAEO論は「順位から推薦へ」という測定と改善の重心移動でした。今回のChangelogは別の実務です。推薦以前に、どの種類のAIトラフィックを通すかを、分類ごとに決めなければならない、という運用問題です。

Searchを残し、Trainingだけを絞る、という設計は公式が提示している分離です。一方、多目的クローラーはSearchとTrainingを兼ねるため、Training側の既定が、発見用の取得まで巻き込むことがあります。ここを見ずに「AIクローラーは全部ブロック」とすると、発見・理解・比較の材料が公式サイトから消え、第三者の古い記述だけが残る、という逆転が起きえます。

WHAT THE DEFAULTS DO｜9/15既定が意味すること

公式が書いている範囲は、次の3点です。

  • 対象は、9月15日以降にCloudflareへ新規接続するドメインの既定である
  • TrainingとAgentは、広告表示ページで遮断。Searchは許可
  • SearchとTrainingを兼ねる多目的クローラーは、Training遮断の既定の影響を受ける

既存ドメインの現行設定を、このChangelogだけで上書きすると読む根拠はありません。新規オンボードの既定と、既存サイトの明示設定は分けて確認します。広告を出していないページでは、この既定の「広告ページ遮断」は発動しません。広告面と情報面が同じURLにある場合は、Searchまで落ちないかを個別に見ます。

WHAT TO CHECK NOW｜今すぐ確認すること

  • CloudflareのAIトラフィック設定で、Search / Agent / Trainingが独立に見えるか
  • 「AI全部ブロック」になっていないか。Training遮断の意図がSearch許可まで侵食していないか
  • 広告を出すページと、会社概要・料金・FAQ・比較材料があるページが同じURLになっていないか
  • 9月15日以降に新規ドメインを載せる予定があるか。載せるなら、既定を受け入れるかオプトアウトするかを先に決めるか
  • 多目的クローラー（SearchとTrainingを兼ねるもの）が、自社の発見経路に入っているか
  • 公式の企業名・提供内容・条件が、Search経由でも読める状態か。遮断後に残るのが第三者ページだけになっていないか

Visibilityの定義と阻害要因は、ここでも使えます。読めない公式ページは、推薦以前に発見で止まります。

ARI LENS｜Visibilityの話であり、実行プロトコルの話ではない

このChangelogが扱っているのは、クローラー分類とページ単位の許可・遮断です。予約や決済の完了手順、取引レール、対話契約の実装ではありません。ARIでは、Searchを残す判断を「発見と理解の材料を公式から供給する」ためのVisibility運用として読みます。Agent分類のリアルタイム取得は、比較や推薦の材料取りに使われることもあれば、別用途であることもあります。公式は用途を3分類で示しているので、ARIもその範囲を超えて断定しません。

WHAT THIS DOES NOT PROVE｜この発表だけでは分からないこと

  • 特定ベンダーのクローラーが、常にSearch / Agent / Trainingのどれか一つにきれいに落ちること
  • Trainingを許可すれば推薦される、Searchを許可すれば引用される、ということ
  • 9月15日既定が、既存ドメインの現行設定を自動で上書きすること
  • 遮断設定と売上・問い合わせ数の因果
  • Cloudflare以外のCDNやWAFで、同じ3分類が同じ定義で使えること

分類名はCloudflareの製品定義です。他社のボット管理画面に同じラベルがあるとは限りません。

NEXT ACTION｜次の一手

まず、Searchを残しTrainingを絞る、という公式の分離を設定画面で確認します。次に、広告ページと情報ページのURLを分けられるかを見ます。新規ドメインを9月15日以降に載せる場合だけ、新しい既定のオプトアウト期限をカレンダーに入れます。推薦や実行の設計は、発見経路が公式サイトに残ってからで十分です。

出典： Cloudflare Developers Changelog, “New options to manage AI traffic,” 2026-07-01。本記事は公式Changelogの範囲で整理しています。既存コラム Cloudflare AEO の「ranking → recommended」論とは論点が異なります。
